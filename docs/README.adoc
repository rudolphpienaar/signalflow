== Purpose

This directory contains several generations of SignalFlow design notes. Not every document is current implementation truth. Some files describe the legacy tree renderer, some describe the board-era engine, and some preserve research or future architecture.

Use this file as the status map before treating an older document as normative.

== Current Reading Path

Read these first for the live `v6.0.21` engine:

1. `../README.md` — project rationale, example flow, and high-level vocabulary.
2. `overview.adoc` — conceptual frame and prior-art relationship.
3. `architecture.adoc` — current engine stack and ownership boundaries.
4. `board.adoc` — board geometry, effective layout, and world materialization.
5. `wiring.adoc` — wiring glyphs, terminal landing, and routing invariants.
6. `wiringSolutions.adoc` — route families and solver doctrine.
7. `yaml_syntax.adoc` — YAML authoring contract.
8. `debugger.adoc` and `repl.adoc` — inspection workflow.
9. `history.adoc` — narrative release and design history.

== Status Taxonomy

`current`: authoritative for the live engine.

`current reference`: mostly current, but may contain historical sections.

`design doctrine`: architectural intent or invariants; not always literal implementation.

`legacy reference`: describes the pre-board renderer or compatibility behavior.

`research / future`: preserved proposal, benchmark, or long-horizon direction.

`artifact`: supporting diagram, text figure, or pseudo-code.

== Current Engine Facts

As of `v6.0.21`, the normal CLI render path materializes a harmonized full-world circuit through the board/world runtime. Per-zone inspection remains essential for debugging, but it is no longer the only or primary implementation truth.

The important current invariants are:

- labels are display text, not route glyphs
- direction markers are mandatory route semantics and must remain visible
- fan-in and fan-out regions are routing substrate, not decorative padding
- terminal edge geometry must reserve enough space for route glyphs, markers, and long labels
- omitted `return` means forward-only, with no blank terminal row and no reverse route
- repeated call labels must be disambiguated before rendering; sftc emits call-scoped parent-side labels for this reason
- route realization must consume resolved geometry, not infer topology from already-rendered text

== Stale-String Hygiene

When changing current docs, search for stale claims before committing:

[source,bash]
----
rg -n 'v6\.0\.7|6\.0\.19|composed-world rendering is intentionally disabled|NOT fully solved|models/node\.py|engine/render\.py' docs
----

Some matches may be intentional inside legacy/history documents, but they should not appear as current implementation claims.
