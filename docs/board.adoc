== Status (v6.0.4)

Board-era architecture is operational for intra routing and now carries the outer-ring path families. Per-zone overlap validation is complete for `back-and-forth.yaml` zones `1,1`, `1,2`, and `1,3`. The production world path now aligns the `1,2` / `1,3` seam by shared chip rows. `WorldGeometryResolver` owns harmonization, `BoardWorldMaterializedSolution` owns materialized world geometry/wiring output, and `signalflow file.yaml` renders the full harmonized world circuit by default.

What is currently complete:

- Intra routing end-to-end: geometry → solve → materialize → render
- Centroid spread (`Ni`/`Si` relaxation) works against a corrected, weighted realized-collision count: signal IDs are extracted from the path text's trailing `.NAME` token (robust across both annotated `[id=]` and bare `_algebraicPathText_build` formats), and collisions on chip-terminal entry rows score weight 2 while free interior rows score weight 1. The weighting drives the relaxation toward spreads that push collisions off pinned rows where they are unfixable by Ni/Si shift.
- `BoardMaterializedSolution` retains the relaxed `regionFramesByName` from `realizationPlan` and renders both `geometry_sprint` and `geometryRelaxed_sprint(legend_show=True)` through a `replace(board, geometry=...)` shadow so the geometry sprint and the wiring sprint share the same frame map. `relaxedRegionFrames_get()` returns the dict directly.
- `_collisionReport_build` aligns its per-cell wire-claim and per-cell direction-set collectors on a single `wireText` key, so the perpendicular-crossing filter is no longer falling back to empty-set lookups and silently classifying real collisions as benign crossings.
- `Em` and `Wm` medial pillars are reserved as 2-column gaps inside the intra substrate.
- Outer geometry (`We`, `Ee`, `Ne`, `Se`, `Wfe`, `Efe`, medials, and transfers) is fully built.
- Outer path topologies are defined and realized; the former zone `1,3` realized collision is resolved in the current materialization path. World seam validation now uses the production `WorldGeometryResolver` / `BoardWorldMaterializedSolution` path, with `signalflow file.yaml` as the default full-world render surface and `snippets/algebraic/world_zone_inspect.py` as a parity/debug surface.
- `algebraicRouteRealization_buildFromPath` now dispatches through a shared realization factory for intra, outer-arc, and outer same-side U-turn paths.
- Effective module boundaries are normalized around visible chip draw extents and then cleared away from valid routing geometry so outer routes remain visible and legal.

== Purpose

This document records the current board-era architecture that backs the quarantine symbolic REPL path.

The important shift is simple:

- routing substrate is now owned by `signalflow.board`
- effective layout doctrine is now owned by `signalflow.board`
- realization is now owned by `signalflow.board`
- the REPL debug layer is now primarily an adapter and inspection surface

This was not a cosmetic refactor. The goal was to remove geometry ownership from legacy debug helpers and move it into one typed, inspectable model that solver, realizer, renderer, and collision checks can all consume.

Current next-step target:

- harden top-level world rendering beyond the current WTE overlap-chain fixture
- keep `WorldGeometryResolver` and `BoardWorldMaterializedSolution` as the core
  world surfaces
- preserve shared chip-row vertical alignment at the `1,2` / `1,3` seam
- preserve horizontal seam alignment through the existing `wOffset` recurrence
- `BoardGeometry` and `GeometryZone` remain the metric runtime truth
- symbolic topology is the intended longer-term semantic top layer

Read with:

- `docs/wiringSolutions.adoc` — routing family reference and current doctrine
- `docs/geometry_symbolic_topology.adoc` — longer-term symbolic topology arc
- `docs/zoneInterconnect_geometry.adoc` — displacement algebra and georule physics

== The Core Distinction

The board package preserves two related but different geometric views:

- substrate board
- effective board

The substrate board is the raw routing substrate lifted from the existing zone and kernel geometry.

The effective board is the doctrine-adjusted operational board:

- effective module boundaries exist as first-class geometry
- chip-terminal envelopes may widen to include visible label/stub extents
- routing core placement shifts accordingly
- chip draw placements and exact terminal positions move with that effective geometry

In normal use, `board` means the effective board.

The substrate view is still preserved for comparison and debugging.

[source,python]
----
kernel = zones.zone_get(1, 1).kernel_get("intra")

board = kernel.board_get()          # effective board
substrate = board.substrate_get()   # raw substrate board
effective = board.effective_get()   # same as board
----

== Why This Distinction Exists

The old system blurred several questions together:

- where routing regions exist
- where module boundaries should be drawn
- how much label clearance is required
- where exact terminal attach points live
- where chip draw blocks should be painted

Those facts are related, but they are not identical.

The effective board exists so that doctrine can change the operational layout without corrupting the raw substrate reference model.

Sometimes:

- effective board == substrate board

But that should be an outcome of doctrine, not an assumption in the API.

== Board Ownership

The current board package owns the following responsibilities.

=== Typed Region Identity

Board regions are no longer keyed by overloaded string parsing alone.

The canonical identity is `BoardRegionId`, which separates:

- region family
- side
- optional qualifiers such as branch or band

Human-readable labels like `west/intra_routing_transition:north` still exist, but they are now a formatted projection of typed identity rather than the source of truth.

=== Geometry

`BoardGeometry` owns:

- region frames
- effective module boundary frames
- exact terminal world positions
- chip draw placements

That makes the board the geometric source of truth for:

- solver lane counts
- materialization attach points
- board render
- collision reporting

This should now be read carefully:

- `BoardGeometry` is the current metric owner
- it is not necessarily the final semantic owner of order and adjacency

The next design direction is to make symbolic topology explicit and then let
`BoardGeometry` realize that topology into concrete frames.

=== Doctrine

`BoardDoctrine` owns explicit geometric policy:

- routing sense
- minimum crossbar span
- effective boundary mode
- `moduleBoundaryPaddingCells`

`moduleBoundaryPaddingCells` is intentionally the single board-domain source of truth for visible clearance inserted after label/stub extent. It is used for both:

- outward effective boundary growth
- inward routing-facing inset between a module boundary and chip content

This prevents label clearance from being recovered accidentally from embedded
render whitespace.

=== Solver

The quarantine symbolic solver surface now derives board-local algebra from the board model instead of raw legacy region counting.

For the current REPL path, the important property is:

- channel lane counts come from board geometry
- algebraic path construction comes from board geometry

=== Realizer

`solution_realize(board, solution)` now realizes solved algebraic paths onto
board-owned geometry.

That means exact terminal positions, route cell walks, and materialized world coordinates are all computed from the same board object the solver used.

=== Rendering

Board-owned rendering now covers:

- board substrate geometry render
- effective boundary overlay
- realized geometry crop and legend assembly
- board canvas composition from chip draw placements plus module boundaries

The REPL materialized render is therefore no longer just a world-render side
effect. It is a board-backed view.

=== Collisions

Materialized collision inspection now exists on the REPL surface:

[source,python]
----
materialized.collisions_get()
materialized.collisions_text()

materialized.boundaryViolations_get()
materialized.boundaryViolations_text()

materialized.occupancyViolations_get()
materialized.occupancyViolations_text()
----

The top-level `collisions_*` view is the catch-all inspection entry point.

== Relationship To Zones

`RoutingZone` and `Board` are not synonyms.

The current intended relationship is:

- `RoutingZone`
  - broader world/topology/placement container
- `Board`
  - routing-substrate and realization domain object for one zone/kernel scope

So the board should be thought of as the routing substrate extracted from one
zone context, not as a replacement for the entire zone abstraction.

== Effective-Boundary Doctrine

The current doctrine for the `WTE` case is:

- module envelopes own chip-terminal space
- fan columns remain outside that envelope
- routing core widths stay invariant
- effective terminal/module growth pushes the outer layout, not the routing
  core widths

This means:

- long channels begin outside the effective module boundary
- fan geometry remains routing substrate rather than module-owned display space
- collision checks can now detect under-box routing as a real geometry
  violation

This same doctrine has also been lifted into the vertical axis for `NTS/STN`
boards so the model is not implicitly horizontal-only.

== Chip Geometry Cleanup

One of the recurring bugs in the migration was accidental reliance on leading
spaces embedded in chip render lines.

That is now split more cleanly:

- `chipDrawGeometry_build(...)` provides semantic chip draw geometry
- `chipDrawLines_build(...)` remains the compatibility render projection

Downstream geometry consumers no longer need to recover box offsets and visible
bounds by reparsing rendered whitespace.

The routing and board builders now consume semantic chip geometry while
preserving the existing render output contract.

This does not mean the render lines are perfectly minimal yet. It means the
board/effective layout is no longer using incidental chip-art whitespace as a
layout source of truth.

== Current REPL Surface

The current recommended board-era REPL flow is:

[source,python]
----
kernel = zones.zone_get(1, 1).kernel_get("intra")

board = kernel.board_get()
substrate = board.substrate_get()
effective = board.effective_get()

substrate.geometry_text(columnOffset=0)
effective.geometry_text(columnOffset=0)

solver = kernel.solver_get(board)
solution = solver.solution_get()
materialized = solution_realize(board, solution)

materialized.wiring_text()
materialized.geometry_text()
materialized.collisions_text()
----

The operational default should remain:

- `board == effective board`

The substrate surface is intentionally explicit and secondary.

== Current Limits

The current board architecture is much cleaner than the legacy state, but it is
not the end of the redesign.

Remaining work includes:

- further shrinking debug-layer adaptation code
- continuing to separate semantic chip geometry from render formatting
- extending parity and doctrine tests beyond the current quarantine fixture set
- eventually retiring still-unused legacy geometry paths once parity is proven

The important milestone already achieved is that solve, realize, render, and
collision inspection now share one board-owned geometric model instead of
recovering that model independently.
