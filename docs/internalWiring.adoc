= Silicon-on-ASCII: A VLSI-Inspired Framework for Manifold Synthesis in High-Fidelity Architectural Schematics
Rudolph Pienaar <rudolph.pienaar@childrens.harvard.edu>
v2.0, March 2026

[abstract]
Silicon-on-ASCII is a formal synthesis framework that renders internal logical manifolds within functional chips using principles derived from VLSI physical design. The chip interior is treated as a routing fabric partitioned into three horizontal bands — an E→W (return) trunk zone at the top, a wall-port and anchor zone in the middle, and a W→E (forward) trunk zone at the bottom. Every logical thread follows a deterministic five-segment Manhattan choreography (W1–W5) through orthogonal Longitude (vertical) and Latitude (horizontal) channel zones. Internal anchor labels, flush against the chip wall with directionality arrows, root every thread to an explicit visual anchor inside the chip. An ironclad non-coincidence mandate is enforced by a post-render Design Rule Check (DRC) engine.

== Introduction

Representing high-density switching matrices in a fixed-width character grid requires more than heuristic drawing. As SignalFlow adopted a Signal Flow Graph (SFG) model with multi-input/multi-output Hub chips, it became necessary to route dozens of concurrent threads through a single chip interior without any two threads sharing a cell. "Silicon-on-ASCII" addresses this by treating the chip as a synthesized physical routing fabric governed by the same density laws and channel disciplines used in VLSI standard-cell layout.

The central failure mode this framework eliminates is _horizontal coincidence_: multiple signals sharing a row, producing prohibited color-bleeding and structural ambiguity. The solution is threefold: (1) reserve dedicated horizontal band zones for each thread class before any wire is drawn, (2) give every thread its own internal anchor label flush against the chip wall, and (3) enforce an algebraic non-coincidence invariant via the `LayoutJoiner` algebra and a post-audit DRC scan.

== Chip Interior Partitioning

The interior of every manifold chip (any chip with `internal_wiring` entries that involve more than 1:1 pass-through) is divided into three non-overlapping horizontal bands:

----
┌──────────────────────────────────────────────────────────┐
│  chip name  (header row y0+1)                            │
├──────────────────────────────────────────────────────────┤  ← y0 + 2 (separator)
│  ──── E→W TRUNK ZONE ────  (return ribbons)              │  rows y0+3 … y0+3+ew_off-1
│  rX◄────────────────────────────────────────────►retX    │
│  (one row per retX→rX manifold pair)                     │
├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤
│  WALL PORT + ANCHOR ZONE  (mid zone)                     │  rows y0+3+ew_off … last anchor row
│  sX► ─── [anchor stack] ─── ◄outX                       │
│  rX◄ ─── [anchor stack] ─── ►retX                       │
│  (wall port rows + stacked internal anchor labels)       │
├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤
│  ──── W→E TRUNK ZONE ────  (forward ribbons)             │
│  sX►────────────────────────────────────────────◄outX    │
│  (one row per sX→outX manifold pair)                     │
└──────────────────────────────────────────────────────────┘
----

The key sizing parameter is the *E→W top offset*:

----
ew_off = ew_top_offset(node)
       = sum(cnt for cnt in ew_src_counts.values() if cnt > 1)
----

where `ew_src_counts[retX]` is the number of times `retX` appears as a source in `node.internal_wiring`. Sources with `cnt == 1` are excluded because they are 1:1 pairs that will be rendered as straight-throughs (no trunk needed). For a hub chip with four callers, `ret2` through `ret5` each appear 4 times → `ew_off = 16`.

=== Band Boundaries

[options="header"]
|===
| Band | First row | Last row | Occupants
| E→W trunk zone | `y0 + 3` | `y0 + 3 + ew_off - 1` | One trunk row per E→W manifold source group, sorted by port name
| Wall port zone | `y0 + 3 + ew_off` | `y0 + 3 + ew_off + spacing*(n-1) + 1` | Chip entry/return rows for left wall (input ports); output signal/ret rows for right wall
| Anchor zone | Adjacent to wall port rows | Last anchor row | Internal anchor label rows, stacked away from their wall port row
| W→E trunk zone | `last_anchor_row + 1` | `y0 + h - 2` | One trunk row per W→E manifold source group, sequential
|===

The chip height formula ensures all zones fit:

----
h = last_wall_return_offset + max_port_density + wiring_count + 2
----

where `last_wall_return_offset = 3 + spacing*(n-1) + 1`, `max_port_density` is the maximum occurrence count of any single port name across all wiring pairs, and `wiring_count` is the total number of wiring pairs with `:`. Because `wiring_count ≥ ew_off + n_we` (total pairs ≥ return pairs + forward pairs), no change to the chip height formula is required when introducing the top zone.

== Longitude and Latitude Zones

Within the chip interior, the horizontal space is further divided into three vertical regions:

----
│ Longitude Zone (Left) │ Latitude Zone │ Longitude Zone (Right) │
│  x0+1 … left_inner-1  │ left_inner … right_inner │ right_inner … rx-1 │
----

=== Longitude Zones (Vertical Bus Strips)

Each port that participates in manifold wiring (not a straight-through) claims a vertical column strip immediately inside its chip wall. The strip width equals the port's connection density (`l_counts[port]`). Strips are allocated inward from the wall:

[source,python]
----
# Left wall: allocate outward from x0+2
for port in left_ports (sorted):
    port_to_x[port] = x0 + 2 + 2 * v_track_l
    v_track_l += l_counts[port]          # consume density columns, not 1

# Right wall: allocate outward from rx-2
for port in right_ports (sorted):
    port_to_x[port] = rx - 2 - 2 * (v_track_r + l_counts[port] - 1)
    v_track_r += l_counts[port]
----

The inner edges of these strips define the latitude zone boundaries:

----
left_zone_inner_x  = x0 + 2 + 2 * v_track_l
right_zone_inner_x = rx - 2 * v_track_r
----

=== Latitude Zone (Horizontal Trunk Space)

The latitude zone is the open horizontal band between the two longitude zones. Thread trunks (W3 segments) traverse this zone. No two threads may share a trunk row in this zone.

== Straight-Through Bypass

Before manifold routing, each wiring pair is tested for straight-through eligibility:

[source,python]
----
if (s_side != d_side            # cross-wall pair
    and src_counts[src] == 1    # source appears exactly once
    and dst_counts[dst] == 1    # destination appears exactly once
    and s_row == d_row):        # wall port rows align
    → straight_through pair: rendered as full-width hline_pierce, no VLSI routing
----

Straight-through pairs bypass the entire manifold machinery. Their wall port rows are seeded into `used_rows` so no trunk can land there. Simple relay chips (`pX()` with `["s1:s1", "r1:r1"]`) consist entirely of straight-through pairs and render as two horizontal lines with no internal anchors.

Straight-through and manifold renderings may coexist in the same chip (e.g., `process()` has `s1:out1` and `ret1:r1` as straight-throughs while all other pairs go through the manifold).

== Internal Anchor Stacking

Every manifold port with N connections receives exactly N internal anchor rows. Anchors are placed adjacent to the port's wall row, extending *away* from the chip center:

[options="header"]
|===
| Port class | Wall | Stack direction | Formula
| Signal (`sX`) | Left | Upward (−y) | `[wall_row - 1, wall_row - 2, …]`
| Return (`rX`) | Left | Downward (+y) | `[wall_row + 1, wall_row + 2, …]`
| Signal (`outX`) | Right | Upward (−y) | `[wall_row - 1, wall_row - 2, …]`
| Return (`retX`) | Right | Downward (+y) | `[wall_row + 1, wall_row + 2, …]`
|===

An `anchor_floor = y0 + 3 + ew_off` constraint prevents signal port anchor stacks from entering the E→W trunk zone. If the upward stack would go below `anchor_floor`, the stack is flipped to extend downward instead:

[source,python]
----
anchor_floor = y0 + 3 + ew_off   # bottom of E→W zone
for port in l_counts:
    if is_signal_port(port):
        rows = [wall_row - 1 - i for i in range(density)]
        if min(rows) < anchor_floor:
            rows = [wall_row + 1 + i for i in range(density)]   # flip to downward
    else:  # return port
        rows = [wall_row + 1 + i for i in range(density)]
        if max(rows) > interior_max:
            rows = [wall_row - 1 - i for i in range(density)]   # flip to upward
    rows = [max(anchor_floor, min(interior_max, r)) for r in rows]
----

=== Neutral Longitude Bus

A neutral (uncolored) vertical bus connects each external wall port row to its anchor stack. This structural connector is never colored — it is overwritten at every anchor row by the sovereign label overlay:

[source,python]
----
# Left wall signal port (anchors above wall row):
canvas.vline(x0 + 1, min(anchor_rows), wall_row + 1, color=None)

# Right wall return port (anchors below wall row):
canvas.vline(rx - 1, wall_row, max(anchor_rows) + 1, color=None)
----

== Internal Anchor Label Overlay (Sovereign)

After all wire routing is complete, anchor labels are written as a _sovereign overlay_ — they punch through whatever the routing engine drew, replacing those cells with the label text. This ensures labels are always visible and human-readable regardless of wire density.

Labels are placed *flush against the chip wall* with zero gap:

[source,python]
----
# Left wall: label at x0+1
label = f"{port}►"       # W→E signal ports
label = f"{port}◄"       # E→W return ports
canvas.text(x0 + 1, anchor_row, label, color=thread_color)

# Right wall: label ends at rx-1
label = f"►{port}"       # W→E destination
label = f"◄{port}"       # E→W source
canvas.text(rx - len(label), anchor_row, label, color=thread_color)
----

The directionality arrow (`►` or `◄`) always appears on the *interior-facing edge* of the label — appended for left-wall labels (facing right), prepended for right-wall labels (facing left). The arrow is rendered in the thread's color.

[options="header"]
|===
| Direction | Port | Wall | Label form | Arrow
| W→E (forward) | `sX` | Left | `sX►` | `►`
| W→E (forward) | `outX` | Right | `►outX` | `►`
| E→W (return) | `retX` | Right | `◄retX` | `◄`
| E→W (return) | `rX` | Left | `rX◄` | `◄`
|===

== Five-Segment Manhattan Choreography (W1–W5)

Every manifold thread follows a deterministic five-segment path through the chip interior. All five segments carry the thread's color — there are no uncolored thread segments:

----
Anchor                 Longitude         Latitude Zone         Longitude        Anchor
(wall col, src_y)       column             (trunk row)           column       (wall col, dst_y)
     ●──── W1 ─────────────●                                      ●──── W5 ────────●
                            │ W2                                   │ W4
                            ●──────────── W3 (trunk) ─────────────●
----

[options="header"]
|===
| Segment | Direction | X span | Y span | Description
| W1 | Horizontal | `wall_x` → `port_to_x[src]` | `src_y` (constant) | Wall anchor to longitude column
| W2 | Vertical | `port_to_x[src]` (constant) | `src_y` → `trunk_y` | Dogleg: longitude column to trunk row (zero-length if already at trunk_y)
| W2_ext | Horizontal | `port_to_x[src]` → `left_zone_inner_x` | `trunk_y` (constant) | Horizontal extension across remaining longitude zone
| W3 | Horizontal | `left_zone_inner_x` → `right_zone_inner_x` | `trunk_y` (constant) | Trunk: full latitude zone crossing
| W4_ext | Horizontal | `right_zone_inner_x` → `port_to_x[dst]` | `trunk_y` (constant) | Horizontal extension across destination longitude zone
| W4 | Vertical | `port_to_x[dst]` (constant) | `trunk_y` → `dst_y` | Dogleg: trunk row to destination longitude column
| W5 | Horizontal | `port_to_x[dst]` → `wall_x` | `dst_y` (constant) | Longitude column to destination anchor
|===

W2 and W4 dogleg segments are skipped (zero-height guard) if the anchor row already coincides with the trunk row. This occurs naturally in the dedicated trunk zone architecture where anchor rows and trunk rows are adjacent.

=== Trunk Row Allocation

Trunk rows are assigned per source group from the appropriate zone:

[source,python]
----
# E→W trunks: scan downward from y0+3, skip only straight-through rows
ew_next = y0 + 3
for src in sorted(ew_h_counts.keys()):
    while any(r in used_rows for r in range(ew_next, ew_next + ew_h_counts[src])):
        ew_next += 1
    thread_to_y[src] = ew_next
    used_rows.update(range(ew_next, ew_next + ew_h_counts[src]))
    ew_next += ew_h_counts[src]

# W→E trunks: sequential from last_anchor_row + 1
we_next = last_anchor_row + 1
for src in sorted(we_h_counts.keys()):
    thread_to_y[src] = we_next
    used_rows.update(range(we_next, we_next + we_h_counts[src]))
    we_next += we_h_counts[src]
----

The `h_counts` dictionary groups wiring pairs by source signal name, so a source with density N claims N consecutive trunk rows. For example, `ret2` with 4 connections claims 4 consecutive rows in the E→W zone. This produces the characteristic colored "ribbon band" appearance for high-density signals.

== Coordinate Resolution

The `VLSIRouter.route_lay` method produces an abstract `Track` in fabric-space `(Channel, Lane)` coordinates. The `canvas_coords_resolve` method maps this to global `(x, y)` canvas coordinates using two dictionaries:

- `port_to_x[port]` — maps a port name to its longitude column x-coordinate
- `thread_to_y[src]` — maps a source port name to its trunk row y-coordinate

This two-level resolution decouples the topological routing from the physical canvas layout, allowing the router to solve the connectivity problem in abstract space and defer coordinate translation to a single pass.

== Collision Detection and DRC

=== OccupancyGrid

The `OccupancyGrid` in `src/signalflow/engine/router/occupancy.py` is a 2D bitset tracking every `(x,y)` cell owned by a colored thread. It provides `trackClear_check` to prove zero coincidence before any segment is committed to the canvas.

=== Post-Render Audit

After the sovereign label overlay, an inline post-audit block asserts the anchor geometry contract:

[source,python]
----
for port, expected_count in l_counts.items():
    wall_row = _wall_row(port)
    actual_rows = all_anchor_rows.get(port, [])
    assert len(actual_rows) == expected_count        # N connections → N anchors
    for r in actual_rows:
        assert r != wall_row                          # no anchor at wall row
    assert len(set(actual_rows)) == len(actual_rows) # no duplicate anchor rows
----

This audit fires on every render, not just in tests. A violation means the geometry contract has been broken and the output is invalid.

=== Algebraic Merging (LayoutJoiner)

The `LayoutJoiner` in `src/signalflow/lib/layout_joiner.py` uses 16-character bitmasks to resolve directional intent at every canvas cell. When `canvas.mode_merge = True`, every character write passes through the joiner, which reactively merges incoming direction intents (N, S, E, W) into the correct box-drawing character (`┼`, `├`, `┤`, etc.). This prevents manual character stamping and ensures that wire crossings produce topologically correct junction glyphs.

=== Synthesis Pipeline (per manifold chip)

1. *Classify pairs* — split `internal_wiring` into straight-through and manifold lists
2. *Render straight-throughs* — `hline_pierce` for each 1:1 cross-wall same-row pair
3. *Compute `ew_off`* — `ew_top_offset(node)` → size of E→W top zone
4. *Build `right_base_rows`* — output port wall rows, offset by `ew_off`
5. *Assign longitude columns* — `port_to_x` via density-weighted `v_track_l/r`
6. *Compute anchor rows* — per port: upward stack (signals) or downward stack (returns), floored at `anchor_floor`
7. *Draw neutral longitude buses* — uncolored vlines from wall port row to anchor stack
8. *Assign trunk rows* — E→W trunks fill top zone; W→E trunks start at `last_anchor_row + 1`
9. *Synthesize W1–W5* — for each manifold pair: `route_lay` → `canvas_coords_resolve` → draw segments
10. *Overlay anchor labels* — sovereign text at `x0+1` / `rx-len(label)`, with `►`/`◄` arrows
11. *Post-audit* — assert anchor count, uniqueness, and wall-row separation invariants

Each colored ribbon occupies exactly one trunk row in the latitude zone and routes through its source port's longitude column (W2 dogleg) before and after the latitude crossing. The anchor labels serve as the visual "patch panel" — every thread is explicitly named at both its source and destination, making execution paths unambiguous to a human auditor.

== AttachmentSense (Deferred)

The `algorithm.pseudo.logic` specification defines a `lineAttachmentSense_determine(src, dst, direction)` function and `AttachmentPolicy` dataclass that govern which end of a latitude or longitude channel a new lane is allocated from (`fromStart` vs. `fromEnd`). This prevents dogleg segments from crossing the other threads of the same port. Current implementation uses positional allocation (sorted port name order); full `AttachmentSense` integration is deferred to a subsequent phase.

== Known Non-Coincidence Limitations

The current anchor row computation does not cross-check anchor rows between different ports. With `portVerticalSpacing = 3` and port density = 4, adjacent ports' upward anchor stacks can share rows. These rows occupy disjoint x-columns (each port's longitude column strip is distinct), so no cell-level coincidence occurs. However, the sovereign label overlay at `x0+1` can overwrite another port's anchor label at a shared row. Full per-port anchor row isolation requires extending the `used_rows` set to include all previously assigned anchor rows before computing each new port's stack — this is a future DRC enhancement.
