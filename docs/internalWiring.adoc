= Silicon-on-ASCII: A VLSI-Inspired Framework for Manifold Synthesis in High-Fidelity Architectural Schematics
Rudolph Pienaar <rudolph.pienaar@childrens.harvard.edu>
v3.3, March 2026

[abstract]
Silicon-on-ASCII is a formal synthesis framework that renders internal logical manifolds within functional chips using principles derived from VLSI physical design. The chip interior is partitioned into non-overlapping horizontal bands (E→W trunk zone, wall-port/anchor zone, W→E trunk zone) and vertical zones (left no-route, left longitude, latitude, right longitude, right no-route). Every logical thread follows a deterministic five-segment Manhattan choreography (W1–W5) through orthogonal Longitude (vertical) and Latitude (horizontal) channel zones. Internal anchor labels — each prefixed by a Structured Junction Bus arm (`┌─/├─/└─` on the left wall; `─┐/─┤/─┘` on the right wall) — root every thread to an explicit visual anchor inside the chip with unambiguous 1→N fan-out topology. An ironclad non-coincidence mandate is enforced by a post-render Design Rule Check (DRC) engine.

== Introduction

Representing high-density switching matrices in a fixed-width character grid requires more than heuristic drawing. As SignalFlow adopted a Signal Flow Graph (SFG) model with multi-input/multi-output Hub chips, it became necessary to route dozens of concurrent threads through a single chip interior without any two threads sharing a cell. "Silicon-on-ASCII" addresses this by treating the chip as a synthesized physical routing fabric governed by the same density laws and channel disciplines used in VLSI standard-cell layout.

The central failure mode this framework eliminates is _horizontal coincidence_: multiple signals sharing a row, producing prohibited color-bleeding and structural ambiguity. The solution is threefold: (1) reserve dedicated horizontal band zones for each thread class before any wire is drawn, (2) give every thread its own internal anchor label flush against the chip wall, and (3) enforce an algebraic non-coincidence invariant via the `LayoutJoiner` algebra and a post-audit DRC scan.

== Chip Interior Partitioning

The interior of every manifold chip is divided into three non-overlapping *horizontal bands* (top to bottom) and five non-overlapping *vertical zones* (left to right).

=== Horizontal Bands

----
┌──────────────────────────────────────────────────────────────────┐
│                          process()                               │  y0+1
├──────────────────────────────────────────────────────────────────┤  y0+2
│  ret2◄──────────────────────────────────────────────────►ret2   │ ┐
│  ret2◄──────────────────────────────────────────────────►ret2   │ │ E→W TRUNK ZONE
│  ret3◄── … one row per retX occurrence … ───────────────►ret3   │ │ y0+3 .. y0+2+ew_off
│  (ew_off rows total)                                             │ ┘
│  s1►────────────────────────────────────────────────────►out1   │ ← straight-through
│  r1◄────────────────────────────────────────────────────◄ret1   │ ← straight-through
│  s2►─ ┊  ┊  ┊  ┊  ┊  ┊  ┊                 ┊  ┊  ┊  ┊  ─ ►out2 │ ┐
│  r2◄─ ┊  ┊  ┊  ┊  ┊  ┊  ┊                 ┊  ┊  ┊  ┊  ─ ◄ret2 │ │ WALL-PORT +
│  s3►─ ┊  ┊  L-long zone  ┊  latitude zone  ┊  R-long zone ►out3 │ │ ANCHOR ZONE
│  …    ┊  ┊  ┊  ┊  ┊  ┊  ┊                 ┊  ┊  ┊  ┊  ─  …   │ ┘
│  s2►──┼──┼──┼──┼──┼──┼──┼─────────────────────────────►out2   │ ┐
│  s3►──┼──┼──┼──┼──┼──┼──┼─────────────────────────────►out3   │ │ W→E TRUNK ZONE
│  … (n_we rows, one per sX occurrence)                   ►out4  │ ┘ last_anchor+1 .. y0+h-2
└──────────────────────────────────────────────────────────────────┘  y0+h-1
----

=== Vertical Zones

Five vertical zones tile the chip interior from wall to wall:

----
x0   x0+1            left_long_start    left_inner  right_inner    right_long_start          rx
│    ╔══ no-route ══╗ ╔══ L-long ═══╗   ╔══════════ latitude ═══════════╗ ╔══ R-long ═══╗ ╔══ no-route ══╗    │
│    ║ label+gap    ║ ║  2×v_left   ║   ║      ≥ 4 cols                 ║ ║  2×v_right  ║ ║ gap+label    ║    │
│    ║ LL+1 cols    ║ ║  cols       ║   ║                               ║ ║  cols       ║ ║ 1+RL cols    ║    │
│    ╚══════════════╝ ╚═════════════╝   ╚═══════════════════════════════╝ ╚═════════════╝ ╚══════════════╝    │
----

Where:

* `LL` = longest left-wall anchor label (`{port}►/◄`), length = `len(port)+1`
* `RL` = longest right-wall anchor label (`►/◄{port}`), length = `len(port)+1`
* `left_long_start = x0 + 2 + LL`  (labels at x0+1..x0+LL, then 1 gap cell)
* `right_long_start = rx - 2 - RL` (labels at rx-RL..rx-1, then 1 gap cell)

The no-route zones are never touched by routing wires. Labels are sovereign overlays that sit in the no-route zone; routing begins one column beyond the gap.

=== Band Boundaries (table)

[options="header"]
|===
| Band | First row | Last row
| E→W trunk zone | `y0 + 3` | `y0 + 2 + ew_off`
| Straight-throughs / wall-port + anchor zone | `y0 + 3 + ew_off` | `last_anchor_row`
| W→E trunk zone | `last_anchor_row + 1` | `y0 + h - 2`
|===

The key sizing parameter is the *E→W top offset*:

----
ew_off = ew_top_offset(node)
       = sum(cnt for cnt in ew_src_counts.values() if cnt > 1)
----

`ew_src_counts[retX]` counts how many times `retX` appears as a source in `node.internal_wiring`. Sources with `cnt == 1` are 1:1 straight-throughs (no trunk needed). For the hub chip with four callers, `ret2`–`ret5` each appear 4 times → `ew_off = 16`.

== Chip Width: `chip_ow_compute`

The minimum manifold chip width must accommodate both label zones, both longitude zones, and at least 4 latitude columns:

----
1 (left border)
+ 1  (junction glyph column)
+ 1  (─ bridge column)
+ LL (left label width)
+ 1  (gap)
+ 2 × v_left  (left longitude columns)
+ ≥4           (latitude zone)
+ 2 × v_right  (right longitude columns)
+ 1  (gap)
+ RL (right label width)
+ 1  (─ bridge column)
+ 1  (junction glyph column)
+ 1  (right border)
= 12 + LL + RL + 2×(v_left + v_right)
----

[source,python]
----
max_left_label  = max((len(n)+1 for n in left_names  if n in l_counts), default=0)
max_right_label = max((len(n)+1 for n in right_names if n in l_counts), default=0)
manifold_min_ow = 12 + max_left_label + max_right_label + 2*(v_left + v_right)
return max(label_w + 2, manifold_min_ow)
----

== Longitude and Latitude Zones

=== Longitude Zone Column Assignment

Every manifold port claims a vertical column strip starting beyond the no-route zone of its wall:

[source,python]
----
# Label widths determine where routing may begin
max_left_label  = max(len(p)+1 for p in left_ports)   # e.g. "s2►" → 3
max_right_label = max(len(p)+1 for p in right_ports)  # e.g. "►out2" → 5

left_long_start  = x0 + 4 + max_left_label   # first col after glyph+dash+label+gap
right_long_start = rx - 4 - max_right_label  # rightmost col before gap+label+dash+glyph

for port in left_ports (sorted):
    port_to_x[port] = left_long_start + 2 * v_track_l
    v_track_l += l_counts[port]

for port in right_ports (sorted):
    port_to_x[port] = right_long_start - 2 * (v_track_r + l_counts[port] - 1)
    v_track_r += l_counts[port]

left_zone_inner_x  = left_long_start  + 2 * v_track_l
right_zone_inner_x = right_long_start + 2 - 2 * v_track_r
----

=== Latitude Zone

The latitude zone spans `left_zone_inner_x` to `right_zone_inner_x` (exclusive). Thread trunks (W3 segments) traverse this zone. No two threads may share a trunk row.

== Straight-Through Bypass

Before manifold routing, each wiring pair is tested for straight-through eligibility:

[source,python]
----
if (s_side != d_side            # cross-wall pair
    and src_counts[src] == 1    # source appears exactly once
    and dst_counts[dst] == 1    # destination appears exactly once
    and s_row == d_row):        # wall port rows align
    → straight-through: full-width hline_pierce, no VLSI routing, no anchor labels
----

Straight-through and manifold renderings coexist in the same chip. For `process()`: `s1:out1` and `ret1:r1` are straight-throughs (same wall-port row, 1:1); all other pairs go through the manifold.

== Internal Anchor Stacking

Every manifold port with N connections receives exactly N internal anchor rows, stacked *away* from the wall port row:

[options="header"]
|===
| Port class | Wall | Stack direction | Formula
| Signal (`sX`) | Left | Downward (+y) if upward would breach `anchor_floor`; else upward (−y) | `[wall_row ± 1, ± 2, …]`
| Return (`rX`) | Left | Downward (+y) | `[wall_row + 1, wall_row + 2, …]`
| Signal (`outX`) | Right | Downward (+y) if upward would breach `anchor_floor`; else upward (−y) | `[wall_row ± 1, ± 2, …]`
| Return (`retX`) | Right | Downward (+y) | `[wall_row + 1, wall_row + 2, …]`
|===

`anchor_floor = y0 + 3 + ew_off` prevents any anchor from entering the E→W trunk zone:

[source,python]
----
anchor_floor = y0 + 3 + ew_off
for port in l_counts:
    if is_signal_port(port):
        rows = [wall_row - 1 - i for i in range(density)]
        if min(rows) < anchor_floor:
            rows = [wall_row + 1 + i for i in range(density)]   # flip downward
    else:
        rows = [wall_row + 1 + i for i in range(density)]
        if max(rows) > interior_max:
            rows = [wall_row - 1 - i for i in range(density)]   # flip upward
    rows = [max(anchor_floor, min(interior_max, r)) for r in rows]
----

=== Structured Junction Bus

A *Structured Junction Bus* replaces the former plain vertical bus. It provides an unambiguous 1→N fan-out visual from each wall port row to its N anchor rows. The bus has two structural layers:

*Wall-row corner* (drawn neutral, no color) — the corner glyph at `bus_x` turns the incoming external wire into the vertical bus:

[options="header"]
|===
| Wall | Port class | Corner glyph | Connects
| Left  | Signal (`sX`, anchors upward)  | `┘` (N+W) | external wire (W) + bus going up (N)
| Left  | Return (`rX`, anchors downward) | `┐` (S+W) | external wire (W) + bus going down (S)
| Right | Output (`outX`, anchors upward) | `└` (N+E) | external wire (E) + bus going up (N)
| Right | Return (`retX`, anchors downward)| `┌` (S+E) | external wire (E) + bus going down (S)
|===

[source,python]
----
bus_x = x0 + 1 if side == "L" else rx - 1
if is_signal_port(port):
    canvas.vline(bus_x, min(anchor_rows), wall_row, color=None)  # connector span
    canvas.set(bus_x, wall_row, "┘" if side == "L" else "└")     # corner
else:
    canvas.vline(bus_x, wall_row + 1, max(anchor_rows) + 1, color=None)
    canvas.set(bus_x, wall_row, "┐" if side == "L" else "┌")
----

*Junction arm* (drawn colored, sovereign overlay) — written at each anchor row in section 2.9:

[options="header"]
|===
| Position | Left-wall glyph | Right-wall glyph
| Farthest anchor from wall (open terminus) | `┌` (signal) / `└` (return) | `┐` (output) / `┘` (return)
| All other anchors | `├` | `┤`
|===

Each anchor row receives three sovereign writes at `bus_x`: the junction glyph, a `─` bridge, then the label text:

[source,python]
----
# Left wall  (rows ordered closest→farthest from wall row)
for i, row in enumerate(anchor_rows):
    is_end = (i == len(anchor_rows) - 1)          # farthest = open terminus
    glyph = ("┌" if is_signal else "└") if is_end else "├"
    canvas.set(x0 + 1, row, glyph, color=thread_color)
    canvas.set(x0 + 2, row, "─",   color=thread_color)
    canvas.text(x0 + 3, row, f"{port}►" if is_signal else f"{port}◄", color=thread_color)

# Right wall
for i, row in enumerate(anchor_rows):
    is_end = (i == len(anchor_rows) - 1)
    glyph = ("┐" if is_signal else "┘") if is_end else "┤"
    canvas.set(rx - 2, row, "─",   color=thread_color)
    canvas.set(rx - 1, row, glyph, color=thread_color)
    label = f"►{port}" if is_signal else f"◄{port}"
    canvas.text(rx - 2 - len(label), row, label, color=thread_color)
----

The junction bus occupies two additional columns per wall (`bus_x` + one bridge cell) beyond the previous plain-bus footprint.

== Internal Anchor Label Overlay (Sovereign)

Anchor labels are written *last* as a sovereign overlay, punching through whatever the routing engine drew. With the Structured Junction Bus, labels start two columns inward from the wall border — the junction glyph (`┌/├/└` or `┐/┤/┘`) occupies `bus_x` and the `─` bridge occupies `bus_x ± 1`, so the text begins at `x0 + 3` (left) or ends at `rx - 3` (right):

[source,python]
----
# Left wall labels (e.g. "s2►", "r2◄") — text starts at x0+3
canvas.text(x0 + 3, anchor_row, f"{port}►", color=thread_color)  # W→E signal
canvas.text(x0 + 3, anchor_row, f"{port}◄", color=thread_color)  # E→W return

# Right wall labels (e.g. "►out2", "◄ret2") — text ends at rx-3
label = f"►{port}"   # W→E dest
canvas.text(rx - 2 - len(label), anchor_row, label, color=thread_color)
----

The directionality arrow (`►` or `◄`) appears on the *interior-facing edge* of every label:

[options="header"]
|===
| Direction | Port | Wall | Label form | Arrow position
| W→E (forward) | `sX`   | Left  | `sX►`  | appended (faces right/interior)
| W→E (forward) | `outX` | Right | `►outX`| prepended (faces left/interior)
| E→W (return)  | `retX` | Right | `◄retX`| prepended (faces left/interior)
| E→W (return)  | `rX`   | Left  | `rX◄`  | appended (faces right/interior)
|===

== Five-Segment Manhattan Choreography (W1–W5)

Every manifold thread follows a deterministic five-segment path. Terminals are offset one cell *inside* the chip wall (`x0+1` for left, `rx-1` for right) so W1 and W5 never pierce the chip border at non-port rows:

----
 no-route   L-long     latitude zone       R-long   no-route
  zone       zone                           zone      zone
│         │        │                    │        │         │
x0  x0+1   x0+2+LL  left_inner     right_inner  rx-2-RL  rx-1  rx
│    ●──── W1 ──────●                            ●──── W5 ────●  │
│                   │ W2                         │ W4            │
│                   ●──────────── W3 ────────────●               │
----

[options="header"]
|===
| Segment | Direction | X span | Y span | Description
| W1 | H | `x0+1` → `port_to_x[src]+2×lane` | `src_y` | No-route zone + L-long to anchor column
| W2 | V | `port_to_x[src]+2×lane` | `src_y` → `trunk_y` | Dogleg: longitude column to trunk row
| W2_ext | H | longitude col → `left_zone_inner_x` | `trunk_y` | Horizontal sweep across remaining L-long zone
| W3 | H | `left_zone_inner_x` → `right_zone_inner_x` | `trunk_y` | Trunk: full latitude crossing
| W4_ext | H | `right_zone_inner_x` → longitude col | `trunk_y` | Horizontal sweep across R-long zone
| W4 | V | `port_to_x[dst]+2×lane` | `trunk_y` → `dst_y` | Dogleg: trunk row to destination column
| W5 | H | `port_to_x[dst]+2×lane` → `rx-1` | `dst_y` | Destination column to no-route zone
|===

W2 and W4 are zero-length when `src_y == trunk_y` (anchor row coincides with trunk row, common in dense manifolds).

=== Trunk Row Allocation

[source,python]
----
# E→W trunks: scan from y0+3, skip straight-through rows
ew_next = y0 + 3
for src in sorted(ew_h_counts):
    while any(r in used_rows for r in range(ew_next, ew_next + ew_h_counts[src])):
        ew_next += 1
    thread_to_y[src] = ew_next
    used_rows.update(range(ew_next, ew_next + ew_h_counts[src]))
    ew_next += ew_h_counts[src]

# W→E trunks: sequential from last_anchor_row + 1
we_next = last_anchor_row + 1
for src in sorted(we_h_counts):
    thread_to_y[src] = we_next
    used_rows.update(range(we_next, we_next + we_h_counts[src]))
    we_next += we_h_counts[src]
----

A source with density N claims N consecutive trunk rows, producing the characteristic colored "ribbon band" appearance.

== Coordinate Resolution

`VLSIRouter.canvas_coords_resolve` maps fabric-space `(Channel, Lane)` to global `(x, y)` via two dictionaries:

* `port_to_x[port]` — longitude column base x for port
* `thread_to_y[src]` — trunk row base y for source group

[source,python]
----
v_x_src  = port_to_x[start.label] + 2 * l_lane_src
v_x_dst  = port_to_x[end.label]   + 2 * l_lane_dst
logical_y = thread_to_y[src_name]  + h_lane

points = [
    (start.x,  start.y),   # W1 start  (x0+1 or rx-1)
    (v_x_src,  start.y),   # W1 end / W2 start
    (v_x_src,  logical_y), # W2 end / W3 start
    (v_x_dst,  logical_y), # W3 end / W4 start
    (v_x_dst,  end.y),     # W4 end / W5 start
    (end.x,    end.y),     # W5 end   (x0+1 or rx-1)
]
----

== Collision Detection and DRC

=== OccupancyGrid

The `OccupancyGrid` in `engine/router/occupancy.py` tracks every `(x,y)` cell owned by a colored thread and exposes `trackClear_check` to prove zero coincidence before committing a segment.

=== Algebraic Merging (LayoutJoiner)

With `canvas.mode_merge = True` every `canvas.set()` call passes through `LayoutJoiner.glyph_merge`, which resolves directional intent bitmasks (N, S, E, W) into the correct box-drawing character (`┼`, `├`, `┤`, …) — so wire crossings produce topologically correct junction glyphs automatically.

=== Post-Render Audit (section 2.10)

After the sovereign label overlay, an inline assertion block verifies the anchor geometry contract:

[source,python]
----
for port, expected_count in l_counts.items():
    actual_rows = all_anchor_rows.get(port, [])
    assert len(actual_rows) == expected_count        # N connections → N anchors
    for r in actual_rows:
        assert r != _wall_row(port)                  # no anchor at wall row
    assert len(set(actual_rows)) == len(actual_rows) # no duplicate anchor rows
----

This fires on every render. A violation means the geometry contract is broken and the output is invalid.

=== Synthesis Pipeline (per manifold chip)

1. *Classify pairs* — split `internal_wiring` into straight-through and manifold lists
2. *Render straight-throughs* — `hline_pierce` for each 1:1 cross-wall same-row pair
3. *Compute `ew_off`* — `ew_top_offset(node)` → size of E→W top zone
4. *Build `right_base_rows`* — output port wall rows, offset by `ew_off`
5. *Compute label widths* — `max_left_label`, `max_right_label` from manifold port names
6. *Assign longitude columns* — `port_to_x` via label-aware `left_long_start` / `right_long_start`
7. *Compute anchor rows* — per port: upward (signals) or downward (returns), floored at `anchor_floor`
8. *Draw neutral longitude buses* — uncolored vlines at `x0+1` / `rx-1`, wall row to anchor stack
9. *Assign trunk rows* — E→W trunks fill top zone; W→E trunks from `last_anchor_row+1`
10. *Synthesize W1–W5* — `route_lay` → `canvas_coords_resolve` → draw segments (terminals at `x0+1`/`rx-1`)
11. *Overlay junction bus arms + anchor labels* — sovereign writes at each anchor row: junction glyph at `bus_x`, `─` at `bus_x±1`, label text at `x0+3` / `rx-2-len(label)`, `►`/`◄` arrows
12. *Post-audit* — assert anchor count, uniqueness, and wall-row separation invariants

== AttachmentSense (Deferred)

The `algorithm.pseudo.logic` specification defines a `lineAttachmentSense_determine(src, dst, direction)` function and `AttachmentPolicy` dataclass that govern which end of a latitude or longitude channel a new lane is allocated from (`fromStart` vs. `fromEnd`). Current implementation uses positional allocation (sorted port name order); full `AttachmentSense` integration is deferred to a subsequent phase.

== Known Limitations

* Anchor row computation does not cross-check rows between different ports. With `portVerticalSpacing = 3` and density = 4, adjacent ports' anchor stacks can share rows. These occupy disjoint x-columns so no cell-level coincidence occurs, but the sovereign label at `x0+1` can overwrite another port's anchor label at a shared row. Full per-port isolation requires extending `used_rows` before computing each port's stack.
