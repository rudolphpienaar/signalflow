== Status

This document is the current architectural reference for the live SignalFlow
engine.

Current checkpoint: the active routing target is independent overlap-zone materialization, not full-world seam/interconnect composition. `back-and-forth.yaml` is the current proof fixture and must validate zones `1,1`, `1,2`, and `1,3` independently before full-board overlap integration resumes.

The older implementation reference now lives in
`docs/legacy-architecture.adoc`.

== Abstract

SignalFlow is now organized around explicit typed sources of truth rather than
render-time recovery of semantics. The current engine is not best understood as
a YAML-to-ASCII renderer with attached routing heuristics. It is a layered
system:

- typed circuit ingress
- typed calling-stack band topology
- synthetic overlap-zone local topology
- typed routing substrate
- doctrine-adjusted effective layout
- board-local solve and realization
- final text projection

The key current architectural boundary is the `board` package. The board owns
the routing substrate, effective geometry, exact terminal positions, chip draw
placements, realization-facing geometry, and board-domain rendering. The debug
REPL remains the primary interactive inspection surface, but it is now mostly
an adapter over board-owned truth rather than the owner of routing geometry.

== The Current Stack

The active engine should be read as:

[source,text]
----
YAML / document dict
  -> CircuitDocumentSource
  -> CircuitDocument
  -> CallingStack band model
  -> synthetic overlap-zone context
  -> local RoutingZone
  -> board_buildFromKernel(...)
  -> Board (substrate / effective)
  -> board-domain solver helpers
  -> board-domain realization
  -> board-domain render + REPL inspection
----

The important rule is:

- geometry should be known before rendering

The engine must not rediscover routing truth from the same glyph artifact it is
trying to paint.

== Current Sources Of Truth

=== Circuit And Topology

`signalflow.engine.input` and the canonical `CircuitDocument` model own the
conversion from raw document dictionaries into typed circuit state.

`CallingStack`, synthetic overlap-zone context construction, and local `RoutingZone` objects own the active zone topology for this phase:

- which calling bands exist
- which adjacent band pair forms the requested overlap zone
- which placements belong to that local zone

Older `RoutingZoneGrid` and `RoutingZoneInterconnect` types remain in the codebase as compatibility and historical topology debt. They are not the current full-board solution target.

=== Board

The current architectural center of gravity is `signalflow.board`.

`Board` is the board-domain object for one zone/kernel scope. It owns:

- typed region identity
- substrate region frames
- effective module boundaries
- exact terminal world positions
- chip draw placements
- board doctrine
- board geometry rendering
- board-local algebraic solve helpers
- board-local realization

This is the current routing-substrate truth boundary.

The detailed board model is documented in `docs/board.adoc`.

=== REPL

The debugger REPL is the primary inspection and design surface, but it should
now be understood as a consumer of board-owned truth.

The key current operational flow is:

[source,python]
----
signalflow examples/simple-circuit/back-and-forth.yaml \
  --run-snippet snippets/algebraic/zone_backedge_wiring.py \
  -- --zone 1,3
----

The detailed REPL surface is documented in `docs/repl.adoc`.

== Substrate Versus Effective Layout

The board model preserves an explicit distinction between:

- substrate board
- effective board

The substrate board is the raw routing substrate.

The effective board is the doctrine-adjusted operational board used for solving
and realization. It carries:

- effective module boundaries
- doctrine-owned terminal/module padding
- doctrine-adjusted chip placements
- exact terminal positions consistent with that effective geometry

In normal use:

- `board == effective board`

The substrate board remains available explicitly for inspection and comparison.

== Doctrine

Board doctrine is no longer implicit glue code. It lives as first-class policy
in `signalflow.board.doctrine`.

Current doctrine includes:

- routing sense
- minimum crossbar span
- effective boundary mode
- `moduleBoundaryPaddingCells`

That padding value is intentionally the current source of truth for visible
clearance around terminal/module envelopes. The architecture should not recover
that clearance from incidental render whitespace.

== Renderer Responsibility

The current renderer responsibility is now split cleanly:

- board package owns board geometry render and board-backed canvas composition
- the REPL materialized render uses board geometry and realized route cells
- the legacy implementation reference remains historical only

This means module boundaries, chip placements, exact terminals, and realized
routes are now intended to agree because they come from one board-owned model.

== What Is No Longer A Good Assumption

The following are no longer good architectural assumptions:

- routing geometry is primarily owned by debug helpers
- module boxes are only late render overlays with no first-class geometry
- solver and realizer may recover geometry independently
- chip draw whitespace should be treated as placement truth
- `RoutingZone` alone is the practical routing-substrate boundary for REPL work

Those assumptions describe the historical path, not the current one.

== Remaining Work

The architecture is cleaner, but not finished.

Important remaining work includes:

- further retiring duplicated legacy geometry logic
- continuing to separate semantic chip geometry from render formatting
- extending parity and artifact tests around board-era doctrine
- continuing to shrink debug-layer adaptation code

The important milestone already achieved is that solve, realize, render, and
collision inspection now share one board-owned geometric model.
