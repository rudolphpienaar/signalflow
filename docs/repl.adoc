== Overview

The new-engine REPL is the primary inspection surface for SignalFlow.

NOTE: The active overlap-zone workflow is per-zone snippet inspection, not old full-world composition. Top-level composed world rendering is intentionally disabled under the overlap-zone architecture. Use `zone_backedge_wiring.py` and `zone_geometry.py` with an explicit `--zone`.

It is not a separate query language. It is a curated Python console over the
actual typed engine state:

- validated `CircuitDocument`
- per-zone overlap contexts
- placed local routing zones
- chip placements
- route obligations
- solved route layers
- materialized board output for the selected zone

The intended use is:

- load one YAML document
- inspect the selected overlap zone directly
- ask concrete geometry questions in the REPL
- refine the engine and docs from those observations

Run it with:

[source,bash]
----
signalflow --engine new --repl path/to/document.yaml
----

Example:

[source,bash]
----
signalflow --engine new --repl examples/branch-converging.yaml
----

To preload one snippet at startup:

[source,bash]
----
signalflow --engine new --repl \
  --load-snippet snippets/algebraic/hub_kernel_solver.py \
  examples/hub.yaml
----

To run one snippet non-interactively and exit:

[source,bash]
----
signalflow --engine new \
  --run-snippet snippets/algebraic/hub_kernel_solver.py \
  examples/hub.yaml
----

== Visual Surfaces

The REPL currently exposes three different kinds of visual inspection. They are
related, but they are not the same thing.

=== 1. Schematic Zone Draw

This is the abstract zone drawing:

[source,python]
----
z = zones.zone_get(1, 1)
z.schematic_text()
----

Use this when you want the zone as a debug schematic rather than a literal
world-canvas crop.

=== 2. Kernel Crossbar Map

To see how the 5 kernels are spatially organized within a zone, first inspect
the zone kernels directly:

[source,python]
----
z = zones.zone_get(1, 1)
z.kernels_get()
----

=== 3. Pixel Region Fill (Per Kernel)

This is the kernel-owned region map:

[source,python]
----
z = zones.zone_get(1, 1)
ki = z.kernel_get("intra")
ki.areas_get().grid_text("pixel")
----

This answers questions like:

- where does `east/intra_routing_fan_in_out` begin
- how wide is `west/intra_routing_longitude`
- which columns belong to the chip terminal region

=== 4. Zone As Materialized Locally

This is the authoritative selected-zone composition. It should not be confused with old full-world rendering.

[source,python]
----
z = zones.zone_get(1, 1)
z.world_text()
----

This is the right surface when the question is:

- what does this zone actually look like inside `world.canvas_print()`
- where do chip bodies and route glyphs land in the final composition

== Life Hacks

=== Pixel Render A Kernel's Owned Regions

When you want to verify spans and ownership bands:

[source,python]
----
z = zones.zone_get(1, 1)
kw = z.kernel_get("west")
kw.areas_get().grid_text("pixel")
----

Useful follow-ups:

[source,python]
----
areas = kw.areas_get()
areas.names_get()
area = z.area_get("east/inter_routing_fan_in_out")
area.frame
----

=== Draw A Kernel's Specific Wiring

If you want to see only the routes solved by a specific kernel:

[source,python]
----
z = zones.zone_get(1, 1)
ki = z.kernel_get("intra")
ki.routes_text()
w = ki.wiring_get()
w.list_text()
w.algebraic_text("App.ts.main().s1")
----

=== Interconnect Surfaces Are Historical

Older REPL notes described direct interconnect inspection. That is not the active overlap-zone workflow. Current work materializes one adjacent-band overlap zone at a time through snippets such as `zone_backedge_wiring.py -- --zone 1,3`.

=== Separate Geometry From Composition

When debugging visuals, ask the question in the right layer:

- `ki.areas_get().grid_text("pixel")` answers geometry ownership
- `z.schematic_text()` answers zone schematic structure
- `z.world_text()` answers final local composition
- full composed-world output is intentionally disabled for the overlap-zone architecture

=== Directed Kernel Wiring

The kernel wiring view is the first symbolic routing surface.

[source,python]
----
z = zones.zone_get(1, 1)
ki = z.kernel_get("intra")
w = ki.wiring_get()
w.list_text()
----

The returned text is one directed wire per line:

[source,text]
----
App.ts.main().query:Worker.ts.run().query
Worker.ts.run().result:App.ts.main().result
----

For one endpoint-scoped symbolic view:

[source,python]
----
w.algebraic_text("App.ts.main().query")
----

== Board Surface

The quarantine routing path is now board-backed.

For a kernel-local routing scope:

[source,python]
----
z = zones.zone_get(1, 1)
ki = z.kernel_get("intra")
board = ki.board_get()
----

The default board is the effective operational board.

Use:

[source,python]
----
board.substrate_get()
board.effective_get()
----

to compare the raw substrate against doctrine-adjusted geometry.

Useful inspection calls:

[source,python]
----
board.backend_get()
board.model_get()
board.geometry_text(columnOffset=0)
board.boundaries_get()
board.boundary_get("module/App.ts")
board.terminals_get()
board.terminal_get("App.ts.main()", "s1")
board.validation_text()
----

=== Materialized Routing

The board also now drives realization and the materialized render surface.

[source,python]
----
solver = ki.solver_get(board)
solution = solver.solution_get()
materialized = solution_realize(board, solution)
----

Then inspect:

[source,python]
----
materialized.summary_text()
materialized.wiring_text()
materialized.geometry_text()
materialized.algebraicWorld_text("App.ts.main().s1")
----

=== Collision Inspection

Collision reporting is now exposed directly on the materialized handle.

[source,python]
----
materialized.collisions_get()
materialized.collisions_text()

materialized.boundaryViolations_get()
materialized.boundaryViolations_text()

materialized.occupancyViolations_get()
materialized.occupancyViolations_text()
----

`collisions_*` is the catch-all surface. The narrower helpers are drill-down
views.

== Practical Loop

A good inspection loop for geometry/render questions is:

[source,python]
----
zone = zones.zone_get(1, 1)
kernel = zone.kernel_get("intra")
board = kernel.board_get()
solver = kernel.solver_get(board)
solution = solver.solution_get()
materialized = solution_realize(board, solution)

board.substrate_get().geometry_text(columnOffset=0)
board.effective_get().geometry_text(columnOffset=0)
materialized.geometry_text()
materialized.collisions_text()
zone.world_text()
materialized.renderedBoard_sprint()
----

That moves from:

- substrate geometry
- to effective geometry
- to materialized board-backed output
- to collision inspection
- to zone-local composed output
- not to full world composition during overlap-zone validation

which is usually the shortest path to the real bug.
